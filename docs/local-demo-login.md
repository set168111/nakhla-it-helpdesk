# Local demo login and private instructor setup

LOCAL DEMO ONLY: mandatory employee authentication, plain loopback HTTP, no MFA.
This is not production authentication certification. Runtime auth values are
generated locally and are never part of the source/package or Git history.

## Fresh clone

Follow [README Run it](../README.md#run-it): create a Python 3.12 venv, install
the pinned requirements, create a private `.env`, then run account provisioning
ONCE before the first Compose start:

```powershell
.venv/Scripts/python.exe -B scripts/setup_demo_auth.py
docker-compose -p nakhla-helpdesk -f docker-compose.yml up --build -d --wait
```

Do not run `--rotate` on an existing installation just to prepare a submission.
The script generates individual demo and separate eval passwords for 15 fictional
employees covering the cases, plus a separate demo-admin password. It prints file
locations only. No accounts are generated by this documentation update.

| Local private output | Purpose | Container access |
|---|---|---|
| `data/auth.sqlite3` | Salted password/token hashes, owners and login records | Existing private data mount |
| `secrets/demo/demo-accounts.json` | Employee demo sheet | App only, read-only |
| `secrets/eval/eval-credentials.json` | Dedicated adapted-runner credentials | Never mounted |
| `secrets/private/demo-admin-credential.txt` | Demo-admin password | Never mounted |

All generated files are Git/Docker-ignored. Never package passwords, password
hashes, tokens, databases, `.env`, browser profiles or private backups. Public
tests use explicitly synthetic throwaway fixtures, not provisioned credentials.

## Instructor handoff

Prefer generation on the instructor's own clone using their own API key and
approved budget. They read the admin credential locally in a trusted editor,
sign in at http://127.0.0.1:8000/demo/login, and obtain employee logins from
`/demo/accounts`. The protected read-only ticket view is `/demo/tickets`.
Admin authentication is separate from employee API authentication.

If access to a controlled demo is agreed instead, privately convey only the
necessary demo credential and access instructions through an agreed secure
channel. Eval credentials are a separate private handoff only if grading on that
same installation is agreed. Never attach credential files, auth databases or
session tokens to a repository, issue, chat transcript, video or submission bundle.
No instructor-specific credential transfer or grading agreement is claimed here.

## Authenticated evaluation-contract change

API paths/JSON shapes are retained, but `/api/chat` and `/api/approve` require
`Authorization: Bearer <runtime-token>` obtained from `POST /api/login`.
Unauthenticated requests get 401; conflicting asserted identity and foreign
conversations get 403. Message text cannot select an employee or authorize a write.
No bypass flag exists. `/api/logout` ends a login; `/api/me` reports its identity.

The adapted `evals/run_evals.py` accepts `--credentials PATH` (default private
`secrets/eval/eval-credentials.json`). Case inputs/expectations/scoring remain,
but unauthenticated original/hidden runners are incompatible until the instructor
agrees a credential-aware harness. S2-02's no-user check now matches sign-in
refusal rather than the original clarification. Historical **65/69** is not a
current authenticated acceptance score. No new live baseline is claimed.

The default simulator is internal on port 8102. The optional
`docker-compose.eval.yml` exposes 127.0.0.1:8102 only for an isolated, separately
authorized eval/check-kit environment; never recreate the retained simulator to
enable it. [Isolated fault demo](isolated-fault-demo.md) uses a separate copy,
project, data and host ports. Keep instructor/provider credentials private when
inspecting effective Compose configuration; do not paste its environment output.

## Preserved state and limits

Startup does not destructively clean historical auth/conversation/action rows;
maintenance is explicit. Do not reset/restore databases or renew draft expiry.
A new message can supersede its conversation's pending draft: use a separate chat
for new tests. Employee and admin logins have separate scope; no public reset or
fault control is exposed by the app. Single-worker SQLite, HTTP and simulator
in-memory tickets remain demo limitations. Production OIDC/MFA is not implemented.
